## 1. 개념: 이게 다 뭔데?

| 용어 | 한 줄 설명 |
|---|---|
| **git** | 폴더의 **세이브 기능**. 게임 세이브 파일처럼, 원하는 시점으로 돌아갈 수 있음 |
| **커밋(commit)** | 세이브 파일 하나. "이 시점의 상태"를 통째로 저장한 것 |
| **GitHub** | 세이브 파일을 **인터넷에 백업**해주는 서비스. git과 이름만 비슷하고 다른 것 |
| **`.git` 폴더** | 세이브 기록이 전부 들어있는 숨김 폴더. 이게 있어야 git 폴더임 |
| **`.gitignore`** | "이건 저장하지 마" 목록 (venv, .DS_Store, 개인 데이터 등) |
| **origin** | 내 GitHub 저장소 주소의 **별명**. 긴 주소 대신 쓰는 단축키 |

### 중요: 아무 폴더나 git이 되는 게 아님
- 그냥 폴더 = git은 존재도 모름 ❌
- `git init` 한 폴더 = 이제부터 감시 시작 ✅ (`.git` 폴더가 생김)
- 한 번 `git init` 하면, **그 폴더 안에서** 뭘 만들든 고치든 git이 다 알아챔

## 2. 🔁 매번 반복하는 3줄 ← 제일 중요

코드를 고칠 때마다 이것만 하면 됨.

```bash
git add -A                    # 바뀐 거 전부 담기
git commit -m "무엇을 했는지"   # 세이브
git push                      # GitHub에 올리기
```

**원칙**
- 기능 하나 끝낼 때마다 한 바퀴 (하루치 몰아서 ❌)
- 헷갈리면 `git status` — 몇 번을 쳐도 안전함
- 커밋 메시지는 **무엇을** 했는지 쓰기
  - ✅ `"목표 탭에 진행률 표시 추가"`
  - ❌ `"수정"`, `"업데이트"` ← 나중에 봐도 뭔지 모름

## 3. 3개의 공간 (장바구니 비유) 🛒

```
① 작업 폴더          ②  장바구니          ③  커밋
 (파일 고침)      →   (add: 담기)   →   (commit: 결제) ⭐
```

`git status`에 뜨는 말로 지금 어디 있는지 알 수 있음:

| 메시지 | 지금 위치 | 다음에 할 일 |
|---|---|---|
| `작업 폴더 깨끗함` | 바뀐 게 없음 | (없음) |
| `커밋하도록 **정하지 않은** 변경 사항` | ① 작업 폴더 | `git add -A` |
| `**커밋할** 변경 사항` | ② 장바구니 | `git commit -m "..."` |

> 장바구니가 따로 있는 이유: 파일 10개를 고쳐도 그중 3개만 골라 저장하고 싶을 때가 있어서.

## 4. 명령어 사전

### 매일 쓰는 것
```bash
git status              # 지금 상태 어때? (제일 자주 씀)
git add -A              # 바뀐 거 전부 장바구니에 담기 (-A = All)
git commit -m "메시지"   # 세이브 (-m = message)
git push                # GitHub에 업로드
git log --oneline       # 세이브 목록 보기 (한 줄씩 짧게)
```

### 새 프로젝트 시작할 때 (처음 한 번만)
```bash
git init -b main                                    # 세이브 기능 켜기
# → .gitignore 먼저 만들기!
git add -A
git commit -m "프로젝트 초기 세팅"
# → GitHub에서 빈 저장소 만들기 (github.com/new)
git remote add origin https://github.com/사용자명/저장소명.git   # 연결
git push -u origin main                             # 첫 업로드
```

- `-u`는 **처음 한 번만**. 이후엔 그냥 `git push`
- GitHub에서 저장소 만들 때 **README / .gitignore / license 체크 해제** (내가 이미 만들었으면 충돌남)

## 5. 에러 읽는 법

에러는 하루에도 수십 번 봄. 겁먹지 말고 **읽기**.

| 메시지 | 뜻 | 해결 |
|---|---|---|
| `command not found: push` | `push`라는 프로그램이 없음 | 명령어는 **`git`으로 시작**해야 함 → `git push` |
| `fatal: not a git repository` | 여긴 git 폴더가 아님 | `cd`로 올바른 폴더로 이동 |
| `LF will be replaced by CRLF` | 줄바꿈 방식 안내 (경고일 뿐) | 무시해도 됨 |
| `Repository not found` | GitHub 주소가 없거나 삭제됨 | 주소 확인 (`git remote -v`) |

> 💡 git은 대부분 **다음에 뭘 하면 되는지 힌트를 같이 줌**. 그거 읽는 습관 들이기.
> 💡 명령어가 성공하면 대체로 **조용함**. 아무 메시지 없으면 잘 된 것.
> 💡 터미널에서 **↑ 화살표** = 이전 명령어 다시 불러오기.

## 6. 저장소(repo) 정리 원칙

- **GitHub 계정은 하나로.** 계정 나누면 활동 기록(잔디)이 쪼개지고 관리만 번거로움
- **나누는 단위는 계정이 아니라 저장소(repo).** 프로젝트 하나당 repo 하나
- **Public/Private**과 **포트폴리오냐**는 별개:

| | Pin 함 (프로필 앞에 내걸기, 최대 6개) | Pin 안 함 |
|---|---|---|
| **Public** | 🏆 제출용·대표작 | 🌱 연습·공부용 (공개해도 부담 없음) |
| **Private** | — | 🔒 미완성 / 개인 데이터 / 비밀키 |

→ 연습용도 Public으로 두면 활동 기록이 쌓여서 오히려 좋음. **Pin만 안 하면** 앞에 안 보임.

### 절대 GitHub에 올리면 안 되는 것
- 비밀번호, API 키, 토큰
- 개인정보가 든 데이터 파일
- `venv` (남이 만든 라이브러리 수천 개)

→ 전부 `.gitignore`에 넣기

- `docker-web` — Docker + Nginx 연습 (Public)
- `aws-practice` — AWS 연습 (Public)

### 저장소를 하나로 합치며 배운 것 (2026-08-06)
- 프로젝트 하나당 repo 하나가 원칙이지만, **일지처럼 그 프로젝트에 붙어있는 기록은 같은 repo 안 폴더로** 두는 게 관리가 쉬움
- 저장소 이름은 **내 계정 안에서만 유일하면 됨.** 남들이 같은 이름을 써도 상관없음
- GitHub에서 삭제한 저장소는 **90일 안에 복구 가능** → https://github.com/settings/deleted_repositories
- 로컬에 `.git` 폴더가 있으면 **역사가 통째로 살아있음.** GitHub은 그 사본일 뿐
